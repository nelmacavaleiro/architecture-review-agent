# Answer key: W5 Planning document storage

Pack: examples/wrenford-borough-council
Proposal: tests/proposals/W5-planning-document-storage.md

Expected overall risk: High
Expected recommendation: Revise and resubmit
Expected status: Ready for architect review

## Expected findings

| # | Reference | Expected result | Expected severity | Where in the proposal | Acceptable alternatives |
|---|---|---|---|---|---|
| 1 | WBC-P03 Cloud first, with AWS as the standard platform | Breach | Medium | Proposed design: new storage server and virtual server in the server room | None |
| 2 | WBC-P04 Use open standards and avoid lock-in | Breach | Medium | Proposed design: internal file format and no bulk export | None |
| 3 | ADR-0001 Use AWS in the London region for hosted services | Conflict | High | Proposed design: a new service hosted in the server room, not on AWS, with no approved exception | May be combined with finding 1 if both references are cited |

## Traps (should not be reported as problems)

- Data stored in the council's own server room and second site: in the UK, and a DPIA has been completed, so WBC-P05 is met.
- Whole-life cost, including replacement after five years: WBC-P08 is met.
- Cloud storage was considered with a reason given: this does not cancel the WBC-P03 breach, but WBC-P06 is met.
- Recovery of 2 working days and 24 hours: NFR-03 applies and is met.
- Accessibility report and testing: WBC-P02 and NFR-04 are met.

## Notes

A good review may question the cost comparison with cloud storage, or note that space and cooling are limited. These are acceptable as questions or Low observations.
