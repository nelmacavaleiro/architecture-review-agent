# Answer key: H1 Partner data feed (contradictory ADRs)

Pack: tests/packs/kestrel-mutual-contradiction
Proposal: tests/proposals/H1-partner-data-feed.md

Expected overall risk: High
Expected recommendation: Revise and resubmit
Expected status: Ready for architect review

## Expected findings

| # | Reference | Expected result | Expected severity | Where in the proposal or pack | Acceptable alternatives |
|---|---|---|---|---|---|
| 1 | ADR health: Accepted ADR-0009 contradicts Accepted ADR-0003 | ADR health issue | Low | Pack: ADR-0009 allows direct database access; ADR-0003 requires all partner APIs to go through API Management | None. This is the main purpose of the test |
| 2 | ADR-0003 Publish all internal and partner APIs through Azure API Management | Conflict | High | Proposed design: direct replica access instead of an API | Raised in the limits and escalation section as a conflict for the architect to resolve, rather than as a High finding |
| 3 | KM-P06 Systems integrate through the API gateway | Breach | Medium | Proposed design: partner reads a database | None |
| 4 | Limits and escalation | Contradiction between ADRs needs an architect's decision | Not graded | Section 12 of the review | None |

## Traps (should not be reported as problems)

- Data in UK South and broker staff in the UK: KM-P01 is met.
- Broker already assessed in 2025: KM-P07 is met.
- Read-only account, credentials in Key Vault with rotation, and access logging: KM-P04 is largely met. A reviewer may note that a managed identity is not possible for an external partner; this is acceptable as a Low observation.
- Not an important business service, with a phone alternative: KM-P02 does not apply.

## Pass condition

The test passes if the review identifies the contradiction between ADR-0009 and ADR-0003 (finding 1) and raises it for the architect (finding 4).
